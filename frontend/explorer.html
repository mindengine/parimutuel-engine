Parimutuel Engine

Everything the engine does, from a distilled Brisnet card to a settled ticket, shown on the real cards in the database.

How it works

Four stages per card

Each card runs through these in order. Scratches come out before anything is ranked, so every rank, pace call and grade describes the field that actually runs. Pick a stage to see its inputs and outputs.

Stages 1–3 output

The cards, graded

Every runner the engine has seen, with the grade, the tags, and the numbers behind them. Grades are from the rules grader unless a card's extras file supplied Grant's.

Grade mix across this card
Stage 3–4 math

What it costs to cover a tier

The engine asks one question of every pool: how deep into the grades did you have to go to have the winners, and what would that coverage have cost? Change the depth and pool type to see the combination count move. These use this card's real grades.

Check slips for overlap

Multi-slip tickets must never pay for the same combination twice. One slip per line, legs or slots split with /. This is the same check the engine runs before logging a ticket.

Storage

Four tables, one file

The database is data/engine_v2.db, a single SQLite file rebuilt from data/cards/ with python -m pe.v2 rebuild. One row per runner carries everything about that horse, from the raw card to the final result.

What it will tell us

Three diagnostic questions

A

Are the grades honest?

Win rate, closing-line value, and flat-bet ROI in win, place and show for every grade and tag combination. An A that wins less than an A should, or a [W] that the market already sees, shows up here first.

view: v_grade_calibration
B

Which pool pays for our work?

For each pool type and tier depth: how often the playable grades caught the winners, what the payout was per combination needed, and whether horizontals paid more than parlaying the winners would have.

view: v_pool_efficiency
C

Where do the rules leak?

Every faded favorite that won and every lone-speed [E] that ran out of the money, grouped by track, distance and pace, with the QSP, purse and layoff numbers that were on the card.

view: v_parameter_leaks
